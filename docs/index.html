#1 Kritická zranitelnost v Apache Roller zneužívaná k RCE

🎯 Cíl: Apache Roller (Java-based group-blogging server).

⚡ Podstata: Zranitelnost v Apache Roller umožňuje neautentizovaným útočníkům vzdálené spuštění kódu (RCE) prostřednictvím deserializace nedůvěryhodných dat v XML-RPC endpointu.

🌍 Co to znamená pro běžné lidi: Útočníci mohou převzít kontrolu nad serverem, pokud používáte starší verzi tohoto softwaru. Je nutné okamžitě aktualizovat na verzi 6.1.6 nebo vyšší.

Rozbalit přeložený článek a technický rozbor

📄 Překlad článku

Apache vydal bezpečnostní aktualizace pro kritickou chybu v Rolleru, kterou útočníci zneužívají k získání kontroly nad servery. Apache Roller je open-source blogovací server založený na Javě. Chyba (CVE-2026-129448) je aktivně zneužívána v reálném světě. Deserializace nedůvěryhodných dat ve verzích 4.0.0 až 6.1.4 umožňuje neautentizovanému útočníkovi spustit libovolný kód. XML-RPC endpoint přijímá typy rozšíření dodavatele a deserializuje je před autentizací požadavku. Jedná se o stejnou zranitelnost jako CVE-2026-82384, která se dříve týkala pouze verze 6.1.5. Uživatelé by měli okamžitě upgradovat na Apache Roller 6.1.6 nebo novější, který zakazuje typy rozšíření a odmítá škodlivé XML-RPC požadavky po vypnutí této funkce. Administrátoři, kteří nemohou okamžitě upgradovat, mohou dočasně zmírnit riziko nastavením 'enabledForExtensions' na 'false' v souboru WEB-INF/web.xml a odstraněním mapování servletu '/roller-services/xmlrpc'.

⚙️ Jak to funguje

Zranitelnost spočívá v nebezpečné deserializaci objektů z XML-RPC požadavků. Útočník pošle speciálně vytvořený XML-RPC požadavek, který obsahuje serializovaný Java objekt. Aplikace tento objekt deserializuje předtím, než ověří identitu odesílatele, což vede k RCE v kontextu běžícího procesu.

🛡️ Mitigace

  • Upgrade na Apache Roller 6.1.6+
  • Nastavení enabledForExtensions na false v WEB-INF/web.xml
  • Odstranění mapování servletu /roller-services/xmlrpc

🎯 MITRE ATT&CK

  • T1190
  • T1203

Skóre: +3 In the wild, +2 Remote exploit bez autentizace, +2 Enterprise software, +1 Veřejný PoC exploit, +1 Privilege Escalation/Lateral Movement, +1 Chybí patch (pro starší verze)

📖 Slovníček pojmů

Deserializace: Proces převodu datového formátu (např. XML nebo binární stream) zpět na objekt v paměti aplikace. Pokud není vstup validován, může vést k RCE.
RCE: Remote Code Execution – schopnost útočníka spustit libovolný kód na cílovém systému na dálku.
XML-RPC: Protokol pro vzdálené volání procedur, který používá XML k přenosu dat a HTTP jako transportní vrstvu.

#2 Kritická zranitelnost Java4Shell v OpenJDK umožňuje RCE

🎯 Cíl: OpenJDK 17.0.6+ a aplikace jako Jenkins, Jira, Confluence, Keycloak.

⚡ Podstata: Zranitelnost v Base64 dekodéru OpenJDK umožňuje útočníkům poškození paměti a potenciální vzdálené spuštění kódu (RCE) v mnoha enterprise aplikacích.

🌍 Co to znamená pro běžné lidi: Chyba v základní součásti mnoha firemních systémů. Pokud provozujete servery s Javou, je nutné prověřit verzi a aplikovat záplaty od dodavatele.

Rozbalit přeložený článek a technický rozbor

📄 Překlad článku

Kritická zranitelnost Java4Shell v OpenJDK umožňuje neautentizovaným útočníkům vzdáleně spustit kód v enterprise aplikacích jako Jenkins, Jira, Confluence a Keycloak. Chyba (CVE-2026-114938) je způsobena poškozením paměti v hardwarově akcelerované funkci pro dekódování Base64. Zranitelnost se týká OpenJDK 17.0.6 a novějších verzí na procesorech x86-64 s podporou instrukcí AVX-512. Speciálně vytvořená data Base64 mohou způsobit přepsání částí paměti Javy, což vede k úniku informací nebo RCE. Výzkumníci z Calif zjistili, že k vyvolání chyby stačí 64 znaků 'A' následovaných rovnítkem. Oracle vydal záplaty 17. listopadu. Dočasnou mitigací je spuštění OpenJDK s parametrem -XX:-UseBASE64Intrinsics nebo -XX:UseAVX=2 pro zakázání AVX-512 instrukcí.

⚙️ Jak to funguje

Chyba je v implementaci Base64 dekodéru, který využívá AVX-512 instrukce pro zrychlení. Při zpracování malformovaného Base64 řetězce dochází k zápisu mimo vyhrazenou paměť (out-of-bounds write), což umožňuje útočníkovi ovlivnit sousední objekty v paměti JVM.

🛡️ Mitigace

  • Aktualizace OpenJDK na opravenou verzi
  • Použití parametru -XX:-UseBASE64Intrinsics
  • Použití parametru -XX:UseAVX=2

🎯 MITRE ATT&CK

  • T1190
  • T1210

Skóre: +2 Remote exploit bez autentizace, +2 Enterprise software, +1 Veřejný PoC exploit, +1 Privilege Escalation, +1 Chybí patch (pro některé distribuce), +2 Dopad na kritickou infrastrukturu

📖 Slovníček pojmů

Base64: Metoda kódování binárních dat do textového formátu pomocí 64 znaků.
JVM: Java Virtual Machine – prostředí, ve kterém běží programy napsané v jazyce Java.
AVX-512: Sada instrukcí pro procesory Intel/AMD umožňující paralelní zpracování dat (SIMD).
